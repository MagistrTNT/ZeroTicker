Поскольку C# тебе знаком, это отличный выбор. Для достижения твоей цели — **максимальной экономии ресурсов** — мы будем использовать **.NET 9 с включенным Native AOT**. Это позволит скомпилировать программу в крошечный нативный экзешник (или бинарник под Linux), который не требует установки тяжелого .NET Runtime и потребляет минимум RAM.

Проект назовем **«ZeroTickerr»** — лаконично и в твоем стиле.

---

## Архитектура проекта

Проект будет состоять из двух независимых частей: **Core** (служба сбора данных) и **View** (визуальный виджет).

### 1. Core (C# Console App)

- **RSS Parser:** Использует `System.ServiceModel.Syndication` для чтения лент.

- **Worker:** Цикл с `PeriodicTimer`, который раз в 10 минут опрашивает источники.

- **Formatter:** Объединяет заголовки в одну строку с разделителями.

- **Publisher:** Записывает результат в `data.js` в формате `const rssData = "..."`.

### 2. View (HTML/CSS/JS)

- **index.html:** Минимальная разметка.

- **style.css:** Реализация «бесконечной» прокрутки через GPU-акселерацию (`transform: translateX`).

- **script.js:** Магия бесшовного обновления. Он будет переподключать `data.js` через создание нового тега `<script>`, чтобы текст обновлялся без перезагрузки всей страницы в OBS.

## Задачи для OpenCode

Вот структурированный список задач (Backlog), который можно сразу брать в работу:

### Task 1: Core — Базовая логика и AOT

- Создать проект Console App на .NET 8/9.

- Настроить в `.csproj` параметры `<PublishAot>true</PublishAot>` и `<OptimizationPreference>Size</OptimizationPreference>`.

- Реализовать класс `RssService`, который принимает список URL и возвращает очищенную строку.

### Task 2: Core — Конфигурация и вывод

- Добавить поддержку внешнего JSON-конфига (список RSS-лент, интервал обновления, путь к выходному файлу).

- Реализовать атомарную запись в файл (запись в темп-файл + переименование), чтобы OBS не прочитал «битый» или пустой файл в момент записи.

### Task 3: View — Телевизионный эффект (CSS)

- Создать контейнер для строки.

- Написать CSS-анимацию с использованием `will-change: transform`.

- **Важно:** Настроить анимацию так, чтобы скорость была константной независимо от длины текста (расчет `animation-duration` через JS на основе ширины блока).

### Task 4: View — Динамическое обновление (JS)

- Реализовать механизм «горячей замены» текста.

- Скрипт должен проверять наличие обновлений в `data.js` раз в минуту и плавно подменять контент в DOM, когда старая строка полностью уходит за экран.

### Технический нюанс для экономии

Чтобы C# решение было по-настоящему «легким»:

1. **Избегай тяжелых библиотек:** Не используй `Newtonsoft.Json`, бери встроенный `System.Text.Json`.

2. **HttpClient:** Используй один статический экземпляр или `IHttpClientFactory`, чтобы не плодить сокеты.

3. **Trim Mode:** При публикации в AOT используй `TrimMode=full`, чтобы вырезать весь неиспользуемый код из бинарника.

> Такой подход позволит приложению занимать в памяти **около 15-20 МБ**, что для C# является практически пределом миниатюризации.
